## 0. 一句话定位

> **PaperLens 不回答"这个词是什么意思"，它回答"这篇论文在什么意义上使用这个词、证据在哪一页，以及它没有告诉你什么"。**

一个面向本科生阅读计算机科学论文的**证据审计型**阅读助手：所有输出都锚定到原文段落，标注来源等级，并在信息不足以支撑判断时**明确弃答**，同时报告论文在该严格意义上没有提供的信息。

## 1. 摘要

阅读 CS 论文的主要障碍并非词汇量，而是**术语在特定论文中的局部含义**与**结论的可信度判断**。同一个缩写在不同子领域可能指代完全不同的概念；同一篇论文也可能在第 2 节定义某术语、在第 5 节以另一种含义使用它。现有 PDF 阅读增强工具（如 ScholarPhi、Semantic Reader）解决的是"给出定义"，而学生真正需要的是"这个解释有多可靠、依据在哪、以及由此**不能**得出什么结论"。

PaperLens 以三个机制回应这一需求：**（1）证据卡**——每条解释附带页码锚定的原文引用、来源等级（显式定义 / 仅附录 / 仅据用法推断 / 全文未定义 / 与领域惯用义冲突）与置信度；**（2）负证据审计**——按报告完整性清单检测论文未提供的信息，并映射到"因此不能断言什么"；**（3）定义漂移检测**——检查同一术语在全文中的用法是否一致。

我们将在 30 篇公开论文、约 200 个术语实例上建立人工标注基准，与"直接投喂全文的自由问答"和"正则抽取定义"两条基线比较，报告消歧准确率、引用精确率与召回、证据充分性、归因忠实度与弃答正确率，并辅以一项小规模用户研究（n = 10）。

**Abstract (EN).** Reading CS papers fails less on vocabulary than on *local meaning* and *evidential trust*. PaperLens turns a reading aid into an evidence-audit tool: every explanation is anchored to a page-level quote, classified by provenance, and accompanied by an explicit account of what the paper does *not* report. We evaluate on 200 annotated term instances against free-form LLM answering and regex-based definition extraction.

## 2. 问题与动机

### 2.1 场景

本科生在课程中需要精读若干 CS 论文。典型动作是：遇到不熟悉的缩写 → 查通用解释 → 继续读。这一动作有两个系统性缺陷：

1. **通用解释覆盖的是"领域惯用义"，不是"本文义"**。缩写歧义是常态而非例外。
2. **解释的可信度不可见**。模型给出流畅解释时，读者无法区分"作者明确写了"与"模型根据上下文猜的"。

### 2.2 案例：ITC

在真实论文中，ITC 可能指美国国际贸易委员会、投资税收抵免、下颞叶皮层、项目总相关（心理测量）等。理想情况下，读者划选后应得到四问的回答：

| 问题 | 理想答案 |
|---|---|
| 本文中指什么 | 一个带来源等级的具体展开，而非并列罗列所有可能义 |
| 作者用它解决什么问题 | 它在方法/实验流程中承担的角色 |
| 哪段原文支持 | 页码锚定的引文，且**单独阅读该段即可支撑结论** |
| 本文没报告什么 | 由此**不能**得出的判断 |

第四个问题是本项目与现有工具的根本分野：它要求系统具备**对自身证据边界的表达**。

### 2.3 现有工具的缺口

| 缺口 | 说明 |
|---|---|
| G1 只给答案，不给来源等级 | 无法区分显式定义与推断 |
| G2 不给"不作判断"的许可 | 无定义时仍强行生成，产生幻觉 |
| G3 不做负证据分析 | 读者无法判断结论强度 |
| G4 不做全文一致性检查 | 定义漂移被静默忽略 |

## 3. 研究问题

- **RQ1（消歧）**：在给定论文语境内，缩写的目标义项能否以显著高于通用知识的准确率确定？准确率如何随歧义度变化？
- **RQ2（证据）**：所引段落是否**足以**（而非仅仅相关）支撑解释？可测量的归因精确率能达到多少？
- **RQ3（负证据）**：系统能否可靠识别"论文未报告"的项目，并将其正确映射到受影响的结论？
- **RQ4（效用）**：与不使用该工具相比，使用 PaperLens 是否提升阅读理解测验成绩与主观可用性？

## 4. 相关工作与差异

| 系统 / 工作 | 做了什么 | 与本项目的差异 |
|---|---|---|
| **ScholarPhi**（Head et al., CHI 2021） | 论文中的术语与符号定义即点即现，位置敏感 | 默认"定义存在且正确"；不判来源等级，不做负证据 |
| **CiteRead**（Rachatasumrit et al., CHI 2021） | 在阅读位置嵌入后续引用段落 | 关注引用关系，不关注术语歧义与结论强度 |
| **Semantic Reader**（Allen AI, 2023） | 增强型 PDF 阅读界面，含引用与术语卡片 | 交互与抽取为主，无系统性忠实度评测 |
| **PaperQA / PaperQA2**（Lála et al., 2023；Skarlinski et al., 2024） | 跨文献 RAG 问答，带引文 | 面向跨文献综述；不审计单篇论文的"未报告" |
| **SciFact**（Wadden et al., EMNLP 2020） | 科学主张验证数据集与模型 | 提供方法学参考（归因评估），非阅读界面 |
| **ACRONYM**（Veyseh et al., Findings of EMNLP 2020） | 缩写识别与消歧数据集 | 通用消歧，不针对单篇论文的语境与证据要求 |

**本项目的增量**（报告需明确陈述）：以单篇论文为单位，将"来源等级""负证据""全文一致性""可测量的弃答"组合为一个可评测的系统，而非在既有工具上增加功能。

## 5. 方法设计

### 5.1 证据卡：核心数据契约

四问直接落为结构化字段，作为 C（术语）与 D（接口）的共同契约：

```json
{
  "surface": "ITC",
  "meaning_in_context": "……",
  "role_in_study": "……",
  "evidence": [{ "page": 3, "paragraph_id": "p3-2", "quote": "……" }],
  "not_reported": [{ "item": "多种子方差", "why_it_matters": "无法据此断言……" }],
  "provenance": "explicit | appendix | inferred | undefined | conflicting",
  "confidence": 0.0,
  "alternatives": [{ "expansion": "……", "rejected_because": "……" }]
}
```

- `alternatives` 字段是**抗幻觉机制**而非装饰：要求模型显式说明为何排除其他义项，可显著降低"直接编一个最像的"。
- `provenance` 与 `confidence` 分离：前者是分类判断，后者是校准量。

### 5.2 来源等级的判定

判定顺序（成本从低到高）：定义模式正则（`ABC (全称)`、`全称, hereafter ABC`、缩写表、脚注）→ 首现位置附近的上下文窗口 → 附录与图表题注 → 模型复核。任一环节命中即给出等级，并记录**依据类型**以便复核。

### 5.3 负证据审计

报告完整性清单（可讨论增删）：

| 类别 | 检测项 | 缺失时被削弱的结论 |
|---|---|---|
| 统计 | 多种子方差 / 置信区间 / 显著性检验 | 不能断言稳定优于基线 |
| 归因 | 逐组件消融 | 不能把增益归因于所提机制 |
| 外部效度 | 域外或跨数据集测试 | 不能声称泛化 |
| 可复现 | 代码、数据、超参、训练细节 | 不能声称可复现 |
| 成本 | 算力与推理开销 | 不能声称实用可行 |
| 局限 | 局限性章节是否存在 | 读者需自行补全边界 |

**措辞纪律**：一律表述为"在可解析的正文中未找到……"，并提供"查看附录 / 补充材料"入口。**"本文未报告" ≠ "我们的解析器没有看到"**，两者必须在界面上区分。

### 5.4 定义漂移与同形异义

- **漂移**：列出该术语全文所有出现位置，比较各处的局部用法；若不一致，标红并给出对照。
- **同形异义集**：`ML`、`DL`、`IR`、`CV`、`MAP`、`NLP`、`ITC` 等，人工标注"本应选哪个义项"，按歧义度分层报告准确率。

### 5.5 检索与验证流水线

提取（页码 / 段落 ID）→ 定义候选检索（正则 + 首现）→ 相关段落检索（BM25，可选重排）→ 受约束生成（仅使用检索到的段落）→ **逐句自检**（判断每句是否被所引段落蕴含）→ 证据回映射到页面坐标 → 卡片渲染。

### 5.6 弃答与校准

当 `provenance = undefined` 或自检未通过时，系统输出"未能确认"及原因，而非降级为猜测。在有标签的子集上计算 ECE 并绘制可靠性图。

## 7. 评测设计

### 7.1 数据集

30 篇公开论文（覆盖 ML / 系统 / HCI 各 10 篇），约 200 个术语实例，其中**刻意包含 40 个"全文未定义但被使用"的负样本**。来源与许可证记录于 `tests/fixtures/`。

### 7.2 标注协议

两人独立标注（义项、证据段落、缺失项），分歧由第三人裁决；报告 Cohen's κ。标注指南需明确"证据段落"的判据：**单独阅读该段即可支撑结论**。

### 7.3 指标

| 维度 | 指标 |
|---|---|
| 消歧 | 义项准确率（按歧义度分层） |
| 证据 | 引用精确率 / 召回；证据充分性（人工 1–5）；逐句归因忠实度 |
| 弃答 | 负样本上的正确弃答率；误弃答率 |
| 负证据 | 与人工清单的 F1 |
| 工程 | 端到端延迟、单次成本 |
| 效用 | 理解测验得分差、SUS |

### 7.4 基线

1. 整页文本直接自由问答（无检索、无结构约束）
2. 正则抽取 `ABC (全称)`
3. 本系统（去掉自检的消融版本 + 完整版本）

### 7.5 用户研究

n = 10，随机分为两条件：使用 / 不使用 PaperLens，阅读同一篇论文后完成 5 道理解题 + SUS 问卷。样本量小，结论表述为"初步证据"。

## 9. 风险与局限

| 风险 | 应对 |
|---|---|
| PDF 解析（双栏、断字、公式）质量不足 | 第 2 周即用 3 篇异构论文压测；失败时明确提示"文本层不可用" |
| 负证据可能误判（附录未被解析） | 措辞限定 + 提供人工核对入口 + 报告误判率 |
| 评测主观性强 | 双人标注 + κ + 公开标注指南 |
| 范围膨胀 | 冻结核心三件套；跨论文术语图、校准图列为加分项 |
| 成本与延迟 | 按 PDF 哈希 + Prompt 版本缓存；先出骨架卡再流式补全 |
| 隐私 | 用户论文仅存本地 `data/uploads`，不入库、不入 Git |
